About this prototype

This tool reads HTML aloud while honouring the 1EdTech data-ssml property. Both JSON shapes described in the specification are accepted:

  • Spec format — each key is an object and the directive applies to the element's whole text content: {"sub":{"alias":"sodium chloride"}}
  • Extended format — each key is an array and each item targets a substring via text: {"sub":[{"text":"W3C","alias":"World Wide Web Consortium"}]}

Supported directives

DirectiveSpec formatEmulated how
sub {"sub":{"alias":"…"}} text substitution before synthesis
break {"break":{"time":"500ms"}} utterance split with a timed silence
prosody {"prosody":{"rate":"fast"}} utterance rate multiplier
say-as {"say-as":{"interpret-as":"characters"}} number / date / time / telephone / character expansion
phoneme {"phoneme":{"ph":"pɪˈkɑːn","alphabet":"ipa"}} no Web Speech equivalent — optional IPA respelling

Speech services

No shipping browser accepts SSML through SpeechSynthesisUtterance: markup handed to it is either stripped or spoken as literal tag text, and there is no capability flag to query. That is why Emulate is the default for the browser voice — it realizes each directive with the primitives the Web Speech API does expose, so data-ssml content is audible today.

The three cloud services below do consume SSML natively. Supply an API key and pick Send SSML to hear the reference rendering of your markup, then switch to Emulate on the same voice to hear how close the browser-side approximation gets. The exact document sent is shown in the Log tab either way.

ServiceCredentialsWord timingNotes
Google Cloud TTS API key Yes — SSML_MARK timepoints Simplest of the three: audio and timings arrive in one response.
Amazon Polly Access key + secret (SigV4) Yes — speech marks, second request Neural voices ignore prosody pitch and silently fall back to a standard voice for say-as interpret-as="characters". The tool warns when it sends markup that will hit this.
Azure AI Speech Resource key + region No — sentence only Word boundaries need the Speech SDK's websocket; the REST endpoint returns audio alone.
ElevenLabs API key Yes — character alignment Partial SSML only. See below.

Partial SSML: ElevenLabs

ElevenLabs is not an SSML engine. It takes plain text with two inline pronunciation tags — <break>, and <phoneme> on the models that apply it — and has no sub, say-as, or prosody at all.

So in Send SSML mode it gets a mixed rendering: the tags it understands are passed through as markup, and the directives it cannot express are emulated client-side before sending. The Sentences tab shows which is which, per sentence. Which tags survive depends on the model, so changing the model in the credentials dialog changes what is passed through:

Modelbreakphoneme
eleven_multilingual_v2 (default)yesno
eleven_flash_v2 (English only)yesyes
eleven_turbo_v2 (English only, deprecated)yesyes
eleven_v3nono

Nothing is lost when a tag is not passed through — it falls back to emulation. Note the corner: no model takes both <phoneme> and multilingual text. For pronunciation that has to hold across a whole item bank, ElevenLabs' own pronunciation dictionaries are the durable mechanism.

Its timing data is character-level alignment rather than named marks, and that maps back to the source in any delivery mode — so ElevenLabs is the one service that highlights words in Emulate mode too.

Keys are held in sessionStorage and cleared when the tab closes, unless you tick “Remember on this device”. They are sent only to the provider's own endpoint. A key in a web page is readable by anyone who can open the page, so restrict it: for Google, limit the key to the Text-to-Speech API; for AWS, use an IAM user scoped to polly:SynthesizeSpeech and polly:DescribeVoices, or short-lived STS credentials.

Known limits

  • On the browser voice, word highlighting depends on boundary events. Chrome and Edge fire them for local voices; Safari and remote/network voices often do not. It is disabled in Send SSML mode because the offsets would point into markup.
  • On a cloud voice, word highlighting comes from timing marks, so it needs Send SSML mode and a service that reports them (Google, Polly).
  • Cloud synthesis is billed per character. Each sentence is synthesized once and cached for the session; changing the voice, mode, or text re-synthesizes.
  • Where a directive rewrites what is spoken (sub, say-as, phoneme), the word highlight covers the whole rewritten span rather than tracking inside it — there is no character correspondence to track.
  • phoneme cannot be delivered faithfully without an SSML-capable engine.
  • Pause/resume behaviour varies by platform; the engine re-issues the current utterance if a voice drops it on resume.
